## 2026-09-30（Day 12）· 检查首页的「筛选交互」

**调用范围**：首页浏览区的三行筛选（类别 / 平台 / 口味）+ 卡片网格 + 计数行 + 筛空提示。

### 逐条对照的结果

| 规则 | 查到什么 | 结论 |
|---|---|---|
| 每个页面只有一个主标题 | 首页 h1 只有一个 ✅；但卡片名用的是 `<h3>`，而全项目没有 `h2` —— 层级从 h1 直接跳到 h3 | ⚠️ **已知未修**（当天决定不动它） |
| 区块之间靠间距分组，不靠加边框 | 三行之间靠 gap 10px 分组 ✅；`.axis-rows` 自带 1px 边框 —— 判为"控件组的边界" | ✅ 通过（保留边框） |
| 正文 16px | `.count-line` 与 `.hint` 原来是 **14px** | 🔧 **已改成 16px** |
| 区块标题 18px 以上 | 筛选区没有区块标题，只有行内标签 | ✅ 不适用 |
| 对比度 | 筛选按钮 `--ink-2`（6.93）／ 选中态 `--brand-lift` + `--ink`（5.23）／ 标签与提示 6.93 | ✅ 全部 ≥4.5 |
| 卡片内边距 16px、间距 12px | `.food-card` padding 16px、`.card-grid` gap 12px | ✅（内边距当天从 14 改成 16） |
| 按钮要有默认 / 悬停 / 不可用三种状态 | 筛选按钮有默认 / 悬停 / 选中 / 焦点环；"不可用"态不存在（任何组合都能点） | ✅ 不适用 |
| 360px 不出现横向滚动 | 四个页面实测零溢出；逐元素扫描无超出视口者 | ✅ |
| 导航在小屏可以折叠 | 未做（当天清单明确「不做与筛选无关的功能」） | ⏭️ 推迟 |
| **可访问性**：内容有变化要播报 | 筛选结果变化时**没有播报** —— 点完筛选，用读屏软件的人听不到"筛出几条" | 🔧 **已加 `role="status"`** |

### 这次改了什么

1. `.hint`（筛空提示、其余三页页头说明）**14px → 16px**
2. `.count-line`（「共 N 个候选，当前显示 M 个」）**14px → 16px**；
   里面的数字 **16px → 18px**（保住"数字更醒目"这层关系）
3. 计数行加 **`role="status"`** → 筛出几条会被念出来。
   **只加这一处**：筛空时它已经念出「当前显示 0 个」，两处同时播报会念两遍

### 「筛选三种情况」实测（真浏览器、真点按钮）

| 情况 | 操作 | 结果 |
|---|---|---|
| 有结果 | 平台 = 美团 | 26 条 |
| 有结果 | 再叠加 类别 = 店 | 8 条 |
| 有结果 | 平台换成 淘宝闪购 | 7 条 |
| **无结果** | 把「店」全删掉 → 类别 = 店 | 「当前显示 **0** 个」+「这一组没有符合条件的条目，换个类别或平台看看。」（16px 显示） |
| **清空恢复** | 两行点回「全部」 | 50 → 50 条 |

全程 **0 报错**；桌面宽度与 360px 窄屏都**零横向溢出**。

### 一个值得记住的事实

内置 50 条数据下，「无结果」**用界面点不出来** ——
5 种口味 × 3 类别 × 3 平台的**全部组合**都至少 1 条
（类别 × 平台的四种组合分别是 18 / 17 / 8 / 7 条）。
所以它只有用户**把某一类删光**才会遇到，上表里的测试就是这么构造的。
